# App Service containers

Every example below is the `steps:` of a `runOnce.deploy` hook unless it says otherwise. Service connections are Azure Resource Manager connections with workload identity federation. Deployment jobs, environments, approvals and output variables are in [deployment.md](references/deployment.md).

`AzureWebAppContainer@1` points the app at an image and sets the output `AppServiceApplicationUrl` ([source](https://learn.microsoft.com/en-us/azure/devops/pipelines/tasks/reference/azure-web-app-container-v1?view=azure-pipelines)). The task does not handle registry credentials: give the app a managed identity with AcrPull and set `acrUseManagedIdentityCreds: true` once in IaC, instead of the ACR admin user ([source](https://learn.microsoft.com/en-us/azure/app-service/configure-custom-container#use-managed-identity-to-pull-an-image-from-azure-container-registry)). Container Instances (for example a migration job) pull the same way: `az container create --acr-identity <id> --assign-identity <id>` ([source](https://learn.microsoft.com/en-us/azure/container-instances/using-azure-container-registry-mi)). Deploy an immutable tag (`$(Build.BuildId)` or a digest), never `latest`. The example is the Fix under [Deployment jobs](references/deployment.md#deployment-jobs).
